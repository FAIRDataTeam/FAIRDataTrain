# Model benchmark — 12 September 2026

The tiers in `README.md` were set by running **real M0/M1 deliverables**, not synthetic
prompts, on adjacent model pairs in identical sandboxes. Every sandbox was an `rsync` copy of
`ReferenceImplementation/` at the same commit, with its own virtualenv; every pass condition
was a command that passes or fails. **Every reported result below was re-run and verified
independently** — none is taken from an agent's own summary.

Three tasks, chosen to sit on the boundaries that actually needed deciding:

| Task | Real work package | Pair | Pass condition |
|---|---|---|---|
| T1 | WP-0.3 — generate pydantic models from the JSON Schemas | haiku vs sonnet | the four protocol fixtures round-trip through generated models |
| T2 | WP-0.4 — the station's `GET /` self-description | sonnet vs opus | the emitted RDF conforms to `StationSelfDescriptionShape` under pySHACL |
| T3 | WP-1.3 — the ODRL evaluator | opus vs fable | `agr-9a01` reproduced; the HealthAI request Refused with the prohibition named |

T3 was phrased **exactly as the plan phrases it**, including the HealthAI fixture that does
not exist. That was deliberate: the scoring question was not only "does it pass" but "does it
notice the criterion is unrunnable, or invent something to get to green".

## Results

### T1 — haiku vs sonnet · **sonnet**

Both produced genuinely generated models (`# generated by datamodel-codegen`), left the
contracts untouched, and passed 4/4 on an independent run. Haiku's comparison was actually
the stricter of the two. Two things separated them:

- **Reproducibility**, which the task required: haiku's generator was not byte-identical on
  re-run — a timestamp *and* a random temp filename (`run-state-ahltqtqu.json`) leak into the
  generated header. Sonnet used `--disable-timestamp` and verified byte-identical output.
- **The contract defect.** Both hit `run-state.schema.json`'s absolute `$ref`, which 404s.
  Haiku worked around it silently and reported success. Sonnet stopped, reproduced the 404,
  and reported it — which is the only reason finding 15 exists.

Cost: haiku 110 tool calls / 378 s; sonnet 29 / 295 s. The cheaper model was also the slower
and more expensive one here.

### T2 — sonnet vs opus · **opus**

Both passed. Sonnet wrote 5 tests and found 1 contract defect. Opus wrote 68 and found 4,
including two that neither sonnet nor the human review had seen: `fdt-p:processingLocation`
declared as an `odrl:LeftOperand` but required as a station property (finding 17), and FDT-O
and `fdt-commons` disagreeing about what a linkage station must declare (finding 18).

Opus also wrote **negative tests unprompted** — `test_the_station_shape_actually_fires`,
`test_ontology_alone_leaves_the_participant_role_unresolved` — proving the checks can fail.
That is the single habit this project most needs, and it was not asked for.

It additionally found a real bug in the metaproject `Makefile` (`make test` ran components
from the checker venv, which has no pytest), now fixed.

### T3 — opus vs fable · **opus, narrowly; both excellent**

Both found that WP-1.3's acceptance criterion does not hold together, and both handled it by
the change protocol — contracts first, `VERSION` 0.5.0 → 0.6.0, `FINDINGS.md`, validators
re-run green, only fixtures and vocabulary touched. Between them they produced findings 19–22.

The difference is in how each resolved `agr-9a01` not being derivable from its own inputs:

- **fable** judged the fixture wrong, corrected it, and said explicitly that the opposite
  reading was a one-line revert. Defensible and honestly flagged.
- **opus** looked for the distinction that would make the fixture *right* — introduced
  `fdt-p:constraintRole` (eligibility vs usage constraints), wrote a normative
  `protocol/agreement-derivation.md`, and then reproduced `agr-9a01` **exactly, by RDF graph
  isomorphism, without editing it.**

The second is the better outcome: it treats an inconsistent fixture as evidence of a missing
concept rather than of a mistake, and it leaves the published fixture intact.

Opus also found the two structurally worst defects of the day — `StationPolicyShape` having
never fired (finding 21) and the contracts' own state mapping violating ADR-026 (finding 22) —
and refused to auto-approve an offer carrying `requiresManualApproval true`, demonstrating the
auto path on a different offer instead. 39 tests vs 20.

Cost was comparable: opus 287k tokens / 71 tool calls; fable 267k / 50.

## What this changed

**The hypothesis was wrong in one direction and right in another.** Fable was expected to be
the default for the hardest work; on the one head-to-head at that tier it was matched and
narrowly bettered by Opus at similar cost. So `contract-steward` and `policy-engine` moved
from fable to **opus** — there is no evidence to justify the more expensive default, and
guessing is what this whole exercise was meant to replace.

Haiku was expected to handle simple tasks; it handled one, and silently routed around a
contract defect while doing so. It keeps **`scout`** (read-only search, where a wrong answer
is visible immediately) and gets nothing that touches a contract — because T1 *looked*
mechanical and contained a contract defect, which is precisely the case that matters.

**Fable keeps `verifier`, for a reason the benchmark itself demonstrates.** Opus and fable
found overlapping but non-identical defect sets on the same task from the same inputs. The
verifier's entire job is catching what the implementer missed, and a different model reading
the contracts independently is worth more there than the same model reading them twice. This
is model diversity as a correctness mechanism, not as a hedge.

## Caveats

One head-to-head per boundary, one task each. T2 and T3 differ in difficulty as well as
model, so the tiers are informed judgement, not measurement. Re-run the pair on any boundary
before trusting it for a class of work it was not tested on — particularly
`contract-steward`, whose blast radius is the whole ecosystem and which has no direct
head-to-head behind it.

The benchmark's most valuable output was not the ranking. It was **eleven contract defects**
(findings 12–22, plus Q9/Q10), every one of them invisible to `make check`, found because
three agents were asked to build something real against the contracts instead of reading them.
